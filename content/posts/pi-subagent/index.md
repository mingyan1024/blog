# 项目规则

## 文件操作需先确认（重要）

在对**文件系统做任何「增、删、改」操作之前**，必须先与我商量、获得明确同意后才能执行。

### 需要先确认的操作

- 新建 / 创建任何文件或目录（包括用 `write`、`touch`、`mkdir`、重定向 `>` 等）
- 删除任何文件或目录（包括 `rm`、`rm -rf`、清理临时文件）
- 修改 / 覆盖任何已有文件的内容（包括 `edit`、`sed -i`、覆盖写入等）
- 重命名、移动文件
- 会间接产生文件的操作（如生成脚本、编译输出、格式化写回）
- **执行 `pip install` 或任何包管理器安装指令**（包括但不限于 pip、conda、npm、yarn 等）

### 无需确认即可执行的操作

- 只读操作：`ls`、`find`、`cat`、`grep`、`rg`、`sed`（不写回）、`git status`、`git diff` 等
- 阅读文件、分析目录结构
- 运行不产生文件副作用的查询命令

### 确认流程

1. 在动手前，先说明：**打算改哪个文件 / 做什么改动 / 为什么**，并用清晰的方式列出具体方案（例如要写入的内容提纲、要删除的路径、diff 摘要）。
2. 等待我明确回复 **「同意执行」**。
3. 收到「同意执行」后，才执行对应的文件操作。

### 注意

- 只说「可以」「嗯」「继续」等含糊回复时，要再次确认是否等于「同意执行」，不要擅自开始。
- 一次确认只覆盖当次商量的那批改动；如果方案变了或范围扩大，需要重新商量。
- 我方明确要求「直接改 / 不用问了」时，可视为对当次任务的一次性授权。

## 改文件必须先备份（重要）

对已有文件做「修改 / 覆盖内容」或「删除」之前，**必须先备份**。备份是规定动作，不因「改动很小」「删掉即还原」而省略。

### 备份要求

- 命名：`<原文件名>.bak-YYYYMMDD-HHMMSS`，放在原文件同目录，保留逐字节原文
- 时间戳取本机当前时间；同一批操作的多个文件用同一个时间戳
- **必须在写入之前完成**。改完之后再补的备份不是回滚点，等同没备份
- 备份后立即确认：文件存在、非空

### 无需备份

- 只读操作
- 新建文件（原文件不存在，没有可备份的内容）

### 例外

- 我方明确说「不用备份」时可以跳过，但你要在动手前把这个决定写明

### 收尾

- 在回复里列出：改了哪些文件 / 备份文件名 / diff 摘要
